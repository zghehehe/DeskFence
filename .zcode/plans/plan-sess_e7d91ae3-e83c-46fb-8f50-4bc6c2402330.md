## 目标

修复重命名编辑框与 Explorer 在 `xxx.txt` 和 `v4flash测试.txt` 场景下的上下/左右留白及换行差异；按用户要求暂不处理编辑框越出栅栏边界，也不修改任何图标提取、图标尺寸、图标位置、静态图标绘制或图标间距代码。

## 1. 只改重命名 EDIT 几何

当前代码有一个已确认的中心偏移：`edit_w` 已改成 `cell_w - 2*scale`，但初始 `edit_x` 仍是 `cell_left - 2*scale`，导致整个框比 cell 中心左偏约 `3×scale`。修复为直接计算：

```text
cell_center_x = fence.left + cell_left + cell_w / 2
edit_x = cell_center_x - edit_w / 2
```

保存未取整的稳定 screen-space center（使用 `f.rect.x + cx + m.cell_w/2`），后续所有宽度变化都围绕它重新定位。

## 2. 让 Edit 的内部格式区成为换行基准

当前 `adjust_rename_edit_height` 用完整字符串的 GDI 总宽度加常数，未读取 `EM_GETRECT`；这正是 `v4flash测试.txt` 首行和第二行不一致的主要原因。

实施一个小型、仅供重命名编辑框使用的几何参数结构，保存：

- 目标 fence DPI metrics；
- 稳定 screen-space cell center；
- 原始 label top；
- EDIT 外框和客户区的水平/垂直 inset。

在设置字体和初始文本后读取当前 EDIT 的 `EM_GETRECT`，并在每次宽度变化后重新读取。宽度迭代采用固定点策略：

1. 以当前文本的 GDI 宽度和已测外框水平 inset 得到候选 outer width；
2. 设置候选宽度；
3. 重新读取 `EM_GETRECT` 与 `EM_GETLINECOUNT`；
4. 若换行/格式宽度仍未稳定，再最多迭代 2 次；
5. 最终按测得的格式区宽度和原生 line count 设置高度。

不再把未经测量的 `14` 和 `8×scale` 当作唯一依据；保留安全 fallback 但明确标注为 fallback。

## 3. 对齐单行上下留白

在字体/文本设置完成后，使用控件当前的 `GetClientRect` 和 `EM_GETRECT` 推导垂直 inset：

```text
format_top + format_bottom = client height - format height
outer_vertical_extra = outer height - client height
```

单行高度直接采用 native-calibrated line height + measured vertical insets；多行高度采用 `line_count × line_pitch + measured vertical insets`。

目标：`xxx.txt` 只占一行，框下方不再多出一整段白色空区；`v4flash测试.txt` 的第二行和行距与原生一致。

## 4. 样式与字体

保持现有已经接近原生的：

- `WS_BORDER`；
- `ES_CENTER`；
- `ES_MULTILINE`；
- `ES_AUTOVSCROLL`；
- `ES_NOHIDESEL`；
- 完整 `SPI_GETICONTITLELOGFONT`。

不根据旧日志盲目添加 `ES_AUTOHSCROLL`，因为它是否参与当前 Explorer 版本的实际换行需要运行时确认；用户本轮重点是几何和留白。

## 5. 只读验证闭环

先用已扩充的只读探针或临时只读输出，确认原生当前实际值：

- `GetWindowRect`、`GetClientRect`、`EM_GETRECT`、`EM_GETMARGINS`；
- `EM_GETLINECOUNT`、`EM_LINEINDEX`、`EM_LINELENGTH`；
- styles、font、DPI；
- 对应的栅栏编辑框相同数据。

用户手动打开原生和栅栏重命名，代理只读采样；不使用自动点击、按键、`SetWindowText`、`SetWindowPos`、截图写文件或创建测试控件。
